# Selector 定向补采方案

日期：2026-10-14。方案已落实为采集代码并完成 CPU 回归验证；尚未启动采集，真实 Isaac 仿真回放待验证。实现与验证情况见 [实现记录](directed_implementation_report.md)。

## 本轮目标

新增训练数据覆盖三个方向。三个库分别验收，不用某一类的高产出来替代另一类：

| 数据库 | 故障事件来源 | 来源与结局要求 | 实际一秒标签 [LP失败, VP失败] |
| --- | --- | --- | --- |
| LP failure / VP safe | 仅 LP 注入额外故障 | VP 不注入额外故障，有效测量和时间戳可用，VP rollout 安全 | [1, 0] |
| VP failure / LP safe | 仅 VP 注入额外故障 | LP 不注入额外故障，有效测量和时间戳可用，LP rollout 安全 | [0, 1] |
| Both failure | LP、VP 都注入额外故障 | 两侧故障效应已进入可观测输入；LP、VP rollout 都失败 | [1, 1] |

本轮新增训练文件继续拒收 VP 故障而仅 LP 失败、LP 故障而仅 VP 失败的反向样本。双失败库本轮限定为双侧故障来源，不把单侧故障引出的另一侧失败混入两个单路库。

标签由同一状态快照下的两个真实 counterfactual rollout 生成，不能根据故障类型直接指定标签。双侧注入并不保证双侧失败：若实际得到 [1, 0]、[0, 1]，不写入双失败库，也不转入要求健康侧无额外故障的单路库。非目标结局只记拒收计数，不重标；少量 [0, 0] 对照另行保存。

三个库采样时机器人都须尚未违反安全判据；物理真值及标签所需状态有效、五帧历史完整。这里的有效不要求受扰传感器没有缺测，否则会错误排除拟采集的缺测故障。

单路库要求故障已在当前或历史观测中产生效应，健康侧整个配对标签窗口内没有额外故障。双失败库要求两侧效应都已可观测，不能在快照之后才突然注入第二侧故障、再用未来双失败给当前输入打标签。允许采恢复阶段，但必须保留明确事件来源，并能确认相应残留效应仍存在。

## 当前实现需要调整的点

1. `supplement.py` 中 lp_map、vp_hard 仅有 85% 的对应单路场景比例，dual 仅有 75% 的双侧场景比例。新增三个专用 profile：LP-only 使用 [0, 0, 1, 0]，VP-only 使用 [0, 1, 0, 0]，Dual-only 使用 [0, 0, 0, 1]；此处顺序为 normal、vp_only、lp_only、dual，表示故障来源比例，不是模型输出概率。
2. OutcomeQuotaSampler 当前按实际标签配额收样，但不校验故障事件来源。新增来源、可观测效应和单路库健康侧检查，之后再按实际结局过滤。双失败库不能沿用“必须有一侧健康”的检查。
3. 保留 `run_selector_outcome_supplement.sh` 现有的 lp_failure、vp_failure、both_failure 三库结构，改为上述专用 profile，并为三个库分别输出来源与结局验收报告。
4. `faults.py` 已支持双侧故障随机先后开始和不同持续时间，但现有调度的基础 strength 与 LP/VP delay 仍有共用关系。补充两侧独立强度、延迟和恢复过程，避免双失败数据只覆盖强度同步变化的一条窄分布。

实际结局配额顺序与故障来源顺序不同，实施时须分开处理：

| 目标库 | 结局配额 [两路安全, 仅LP失败, 仅VP失败, 双路失败] |
| --- | --- |
| lp_failure | [0, N, 0, 0] |
| vp_failure | [0, 0, N, 0] |
| both_failure | [0, 0, 0, N] |

N 为通过全部验收的样本数，不是故障尝试次数。

## VP 扰动设计

当前 g1_renet 的深度预处理已有距离相关高斯噪声和概率触发的 3×3 模糊。Selector 的 VP 故障主要为冻结、延迟、固定遮挡、整图缩放、偏置、整数平移、全图塌缩；compound 与 burst 组合这些操作。新设计重点增加空间结构、时间连续性和有效但错误的观测。

| 机制 | 设计重点 |
| --- | --- |
| 不规则局部缺测 | 多块连通区域、条带、软边界，优先覆盖当前图像中的近处地面或障碍边缘；位置与面积随时间连续变化 |
| 边缘深度错配 | 在台阶或障碍的深度突变处混入前景/背景深度、产生局部错值；不把整张图变成无效数据 |
| 空间相关度量误差 | 使用平滑偏置场、局部尺度误差与缓慢漂移，保持多数像素为合法有效深度 |
| 运动相关几何误差 | 小角度姿态偏差、亚像素视野偏移或局部形变，扰动程度随当前可观测运动状态变化 |
| 时间失配 | 时延抖动、连续短时停帧、两帧间隔异常；另建时间滤波拖尾机制，并与通信延迟区分 |
| 动态遮挡与同侧复合故障 | 遮挡逐渐进入、移动、离开；组合少量有明确含义的 VP 机制，例如延迟加局部缺测。VP 单路库只叠加 VP 机制；双失败库再与 LP 机制组合 |

需要有一定比例的“多数深度仍有效、数据包仍新鲜，但几何内容错误”的目标样本，避免只依赖 valid_ratio 或 frame_age 就能判断故障。具体占比由先导采集的产出与多样性确定。

数值扰动在环境已处理的源帧上还原为米，再裁剪和归一化；不重复运行环境原有的高斯噪声或模糊。0 无回波、NaN/Inf、有效前景返回分别遵守本地部署 `training` 模式的预处理语义；原始有效支持在填充前计算。健康特征从受扰后的数据、支持和时间戳重新计算，不手工设成异常。这些机制是输入层的替代模型，不声称实现了完整物理相机渲染。

每张源帧只应用一次相应扰动，保存在 VP 两帧历史中，后续不重写旧帧。时间扰动、遮挡轨迹、相关噪声状态与逐环境 RNG 都进入快照恢复，保证 LP/VP 配对回放比较公平。

## LP 扰动设计

优先覆盖持久地图位姿/高度漂移、局部缺测、地图错位、人员进入离开后的残留，以及同侧复合干扰。LP 单路库中 VP 保持其正常背景噪声和数据路径，不额外注入 VP 故障；仍以实际 [1, 0] 的回放结局验收。这些 LP 机制也用于下面的双失败库。

## 双路失败扰动设计

目标是补充“当前机器人尚安全，但沿 LP 或 VP 分支继续执行，一秒内都违反原安全判据”的状态。这类 [1, 1] 标签训练 q3；它不表示任何可能的切换序列都无法救援，也不直接定义停车、阻尼或其他新控制动作。

### 机制组合

| LP 机制 | VP 机制 | 要补充的困难情况 |
| --- | --- | --- |
| 地图高度/位姿缓慢漂移、局部错位 | 空间相关深度偏差、障碍边缘错配 | 两侧输入大部分有效、时间戳正常，但各自的几何判断都可能错误 |
| 局部地图缺测、更新滞后 | 抖动时延、短时冻结、时间滤波拖尾 | 地形或运动变化时，两侧都拿不到足够准确的当前环境信息 |
| 人员离开后地图残留、局部错误占据 | 移动遮挡、局部前景/背景混合 | LP 保留旧环境内容，VP 同时出现新的局部观测错误 |
| 上述任一持续性 LP 故障 | VP 同侧复合机制，如延迟加局部缺测 | 一侧长期退化，另一侧出现短时复合退化，形成两侧风险重叠的窗口 |

“LP 全空加 VP 全图塌缩”等明显故障可保留少量作对照，但不作为主力。需要同时覆盖：两侧仍有效但错误；一侧明显异常、另一侧仍有效但错误；两侧都明显异常。这样 q3 才有机会学到共同失去安全性，而不是只识别两个失效标志。

每种组合先验证是否真的产生预期观测效应，以及是否与场景几何相容。单纯在平地上增加很大的噪声、依然没有 [1, 1] 产出时，不持续放大到全图失效来凑数；先排查地形、命令、采样阶段和故障作用位置。

### 时间关系与采样窗口

分别覆盖同时开始、LP 先开始、VP 先开始。错峰先导可从 0.1–0.5 秒开始探索，这是试采参数范围，不是已经测得的真实硬件故障时延。两侧强度、持续时间与恢复速度分别变化，不要求相同。

主采样窗口是两侧实际受扰效应的重叠期，也包含一侧恢复但仍有残留、另一侧继续退化的状态。残留包含仍保留在 VP 两帧输入或 selector 五帧历史中的受扰信息。第二侧尚未产生可观测效应时不进入双失败目标库；两侧输入与历史完全恢复后若仍产生 [1, 1]，需单独审计物理状态与来源，不混作持续双侧观测故障。

按两路首次失败时间分别审计，并记录距较早一次失败的时间。可先使用 0–0.2 秒、0.2–0.5 秒、0.5–1.0 秒三个区间检查覆盖，不强制相同比例。重点检查是否全是临近摔倒的最后一帧；若绝大部分在一个控制步内就失败，需前移采样并检查更早状态是否仍实际满足 [1, 1]，不能把原本 [1, 0]、[0, 1] 或 [0, 0] 的早期状态重标。

### 双失败库专属验收

- 两侧故障来源明确，受扰效应已进入 selector 当前输入或历史，快照后不存在不可观测的新故障起点。
- 采样起点满足原安全条件；不能把已经倒地、接触躯干或已经超限的状态当成未来风险正例。
- 同一快照分别执行 LP、VP 的原一秒回放，保留原动作渐变。每侧重复两次，四次回放均有效且各自失败标签一致，最终标签确为 [1, 1]。
- 两侧首次失败时间、失败原因、故障参数、效应支持区域及恢复阶段可追溯。重复回放的时间或原因差异仍按现有审计记录，不能把“失败标签一致”说成轨迹完全一致。
- 故障来源、强度档位、目标库名称和未来失败时间仅作审计与采样依据，不加入 selector 输入，避免模型获得部署时不存在的信息。

## 采集流程与验收

1. 独立先导配置：每个目标库先收 10,000 条，三库合计 30,000 条验收合格样本。分别统计每种机制的尝试数、来源合格数、回放稳定数及目标结局产出率；双失败库再按机制组合和时间先后分组。现有正式 runner 至少 100,000 条的限制需要与先导 runner 分开。
2. 先导稳定后，三个库各正式新增至少 100,000 条，合计至少 300,000 条。每事件最多 8 条、间隔至少 0.2 秒，保留真实仿真时间推进和分散采样。每库 100,000 条因此至少需要 12,500 个事件身份；双侧组合的整段事件使用同一父事件身份，不能按 LP/VP 分开计数来绕过限制。
3. 审计故障建立、持续和恢复阶段，以及地形、命令速度、当前执行分支、驻留区间与首次失败提前量。双失败库增加双侧效应的重叠时间、先后顺序和独立强度覆盖；用这些维度检查覆盖，不强制填满所有笛卡尔组合。
4. 三个库都执行两次 LP 和两次 VP 回放，均需有效且各侧一秒失败标签一致。新增机制的参数、实际观测效应及拒收原因写入报告。单路库分别报告反向失败与双失败拒收数，双失败库报告仅单路失败与两路安全拒收数。
5. 保留原冻结 RENet 权重与 FP32/no-TF32 推理身份，标签仍为原一秒安全定义并包含原五步动作渐变。
6. 定向训练数据与原训练集混合，继续沿用原训练地形/来源分区，避免同一事件及相邻状态进入不同数据分区。三个库各收 100,000 条是采集覆盖目标，不代表训练时必须等权，更不代表双失败的真实发生率变成三分之一。训练混合比例另行对照，概率在原 validation 分布上重新校准。
7. 原 validation 用于选择模型和阈值；原 test 用于既定方案的最终比较，不用于逐轮调参。不能把按结局筛选的补采库当成自然分布测试集。双失败效果同时看 q3 的召回率、精确率，以及对 [1, 0]/[0, 1] 正确救援的误阻挡，不能只靠降低双失败保持阈值来提高召回。

附加建议：可另外保存少量“同一种单路或双路新故障出现，但两路仍安全”的 [0, 0] 对照数据，使用同样的初始安全与回放验收。这不包含本轮排除的反向失败样本，能帮助模型区分故障存在与策略真正失去安全性，尤其避免模型看到双侧故障就直接输出高 q3。它不占三个失败目标库的配额。

## 实施顺序

三个专用 profile、来源与结局过滤、新 VP 机制、历史帧缓存、双侧独立调度、快照恢复以及分析与脚本验收已经实现。下一步在完整 Isaac 环境完成真实回放检查和三库先导采集，再根据实际产出、多样性和失败提前量确定正式参数，最后启动正式采集。

先导入口：`bash legged_lab/selector/run_selector_directed_pilot.sh`，默认各库 10,000 条。正式入口：`bash legged_lab/selector/run_selector_outcome_supplement.sh`，默认各库 100,000 条。两者均使用三个纯来源 profile，保留四次配对回放、原一秒标签与事件限制。
