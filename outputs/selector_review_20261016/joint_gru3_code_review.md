## 1. 训练前建议处理：默认类别加权受批次组成影响

- 包内 `legged_lab/scripts/train_selector_joint.py:44` 和 `legged_lab/selector/run_selector_joint_training.sh:53` 默认开启 `sqrt_inverse_frequency`，与此前建议的第一版等权 CE 不同。
- `legged_lab/selector/joint_model.py:93` 使用 `F.cross_entropy(..., weight=w)` 的默认 mean 归约，即除以当前批目标类别权重之和。
- `legged_lab/selector/joint_training.py:47` 仍使用当前仓库 `ShardBatchSampler`。它打乱 shard 顺序和 shard 内顺序，再连续组成批次，并非全局跨来源混合抽样。真实 LP 定向库前两个 shard 各 8192 行，在 batch=4096 时会出现纯 LP 失败批次。
- 纯类别批次的 CE 中，类别权重在分子分母相消；因此权重效果取决于同批数据的组成。辅助 BCE 不会纠正这一点。
- 训练日志按样本数平均各批次损失，而验证对完整验证集一次计算加权损失，两者也不是完全相同的归约目标。



第一轮可通过 `SELECTOR_CLASS_WEIGHTING=none` 避开此问题。后续保留加权时，应明确按样本计算后乘权重、采用固定分母并规范权重整体尺度，同时设计跨来源混批。非均匀 CE 权重与等权边缘 BCE 的目标取舍，也需要单独对照和校准。

## 2. 比较结果时：网络和决策规则同时改变

`joint_model.py:103` / `joint_training.py:128` 使用四分类 argmax：预测 0 保持，预测 1 选 VP，预测 2 选 LP，预测 3 保持并告警。

这是明确的新决策基线；相较旧方案，同时改变了网络、损失和决策映射。新旧整个流程可以比较，但不能把改善全部归因于 3 层 GRU 或辅助 BCE。建议把同一模型的预测分别接入待比较规则，或至少在相同 argmax 规则下比较统一网络各消融组。

包内 `joint_training.py:150` 将 `selection/low_risk_hold_count` 定义为“预测类别为双安全”的数量；旧 `learned_outcomes` 的同名指标统计 `q0 >= 安全保持阈值`。因此从 0 条变为非零，不能直接证明原阈值保持机制得到改善。建议将新口径命名为 `predicted_both_safe_hold_count`，或者在比较表中明确口径。主要双失败告警也改为 argmax 类别 3，与旧 q3 阈值告警不同。

报告已正确声明只评估逐样本请求，没有执行驻留、连续确认、健康门控和动作混合；这些结果不能当作闭环摔倒率。
