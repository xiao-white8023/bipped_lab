# G1 RENet：感知选择器与双失效停止站立方案

本文是接入设计，不代表选择器或安全策略已实现、训练或通过仿真。目标已确认：视觉失效时使用激光雷达，激光雷达失效时使用视觉，两路都不可用时减速停止并持续站立。

该目标假定 IMU、关节编码器、执行器和底层控制仍正常。站立能力需要在存在可支撑落脚点、且机器人仍能恢复平衡的状态范围内验证；传感器双失效后不能保证在未知悬崖、腾空或已经不可恢复的状态下站稳。

## 1. 当前代码与目标的差距

- `legged_lab/envs/g1/RENet_cfg.py` 的 `RENetTrainCfg`：默认每 20 个训练迭代轮换 LP/VP。
- `legged_lab/envs/g1/RENet_env.py` 的 `sample_renet_estimator_mask()`：支持 alternate、random、lp、vp，没有健康状态驱动的选择器。
- `rsl_rl/rsl_rl/modules/renet_actor_critic.py`：LP 和 VP 是两个估计分支，共用一个 Actor。输入形式为 `current_proprio | mask*z_lp | (1-mask)*z_vp`。
- mask 在 `_split_actor_obs()` 中被裁剪到 `[0,1]`。把 mask 写成 2 会变成 LP，不能表示安全模式。即使另外把两路 latent 都置零，现有模型也没有因此获得停止站立能力。
- 当前 proprio 每帧 78 维：角速度、重力投影、速度命令、23 维关节位置、23 维关节速度、23 维上一动作。真实根部线速度和仿真接触信息在 Critic 侧。
- `sim2sim_renet.py` 已支持激光雷达丢包、深度归零及手动 LP/VP 切换，可扩展成故障评估平台；这些功能尚不等于自动故障切换。

现有训练提供了两种感知输入下的控制基础，但训练轮换本身不能证明检测延迟、故障发生时的切换以及恢复过程可靠。

## 2. 推荐结构：两个可用性判断 + 三状态监督器 + 独立安全策略

保留现有 RENet 观测和权重契约，在外层设置 `VP=0`、`LP=1`、`SAFE=2` 三个状态。只有前两个状态转换成原有 mask；SAFE 调用单独的本体感知策略。

| 视觉可用 | 雷达可用 | 决策 |
|---|---|---|
| 是 | 是 | 当前健康模式优先；启动偏好单独配置 |
| 否 | 是 | LP，原模型 mask=1 |
| 是 | 否 | VP，原模型 mask=0 |
| 否 | 否 | SAFE，停止站立策略接管 |

“可用”指该输入足以支持当前控制任务，不能只看设备是否连接。对尚未初始化、数据过期或置信度不足的输入，先按不可用处理。

监督器至少保存：当前状态、两路健康状态、恢复持续时间、最近有效数据时间和切换原因。采用不同的失效/恢复阈值，恢复需持续有效且历史帧已更新。明显断流等硬故障直接取消对应分支资格，不能被普通切换冷却时间阻塞；两路都无资格时直接进入 SAFE。

退出 SAFE 需要：至少一路持续恢复、该分支历史输入有效、机器人已处于可切换状态。先保持零命令，确认接管稳定后再按经过训练验证的方式恢复运动命令。等待恢复期间持续运行平衡控制。

### 2.1 第一版选择器不需要强化学习

先实现规则健康检测，建立可解释基线，再增加学习模块识别更隐蔽的退化。

视觉侧建议记录：

- 真实采集时间、帧序号、断流时长；重复读取不算新帧。
- 原始深度的无效比例、量程边界饱和比例及关键前方区域覆盖率。
- 与机器人运动相结合的帧间变化，辅助识别冻结图像；静止场景不应仅因画面相同被判故障。
- 可选的图像异常分数或经过标定的质量网络输出。

`get_processed_deepcamera()` 当前会把 NaN/Inf 替换成最大深度，随后模糊、裁剪和归一化。因此原始有效性必须在此处理之前记录，不能只检查归一化后的有限数值。

雷达侧可以复用 `extras["observations"]` 中的 `lidar_valid_ratio`、`lidar_confidence`、`lidar_scan_count`、`lp_frame_age`、`lp_missing_duration`，并补齐：

- 与 Actor 实际消费的高程包一致的置信度、采集时间和关键区域覆盖率。
- 新包是否到达，以及滚动地图中有效格子的年龄。
- 部署端建图所依赖的位姿质量；雷达有点云不代表地图正确。

存在包延迟时，当前 `lidar_confidence` 与延迟后的 `lp_height_history` 可能属于不同时间。应输出 `HeightSnapshotHistory.read()` 返回的 `conf_history`，同时考虑包龄；不能拿新包置信度证明旧包可用。

有效率需要按实际 LP 契约和足下/前方相关区域标定。物理 MID-360 的近场覆盖、`pgtt_full` 与 `pgtt_front` 的覆盖范围不同，不能共用一个未经验证的全图阈值。历史地图不能因为仍有数值就无限期保留可用资格。

### 2.2 如需训练选择器，学习两路独立可用性

推荐输出两个独立 sigmoid 分数 `p_v, p_l`，分别表示视觉和雷达可用性。它们允许同时高、同时低。只在 VP/LP 之间使用二分类 softmax，会在两路都坏时仍被迫选出一个。

候选输入为每路传感器质量指标、短期历史、各自编码特征以及本体运动状态。质量网络在部署时只能使用实际可获得的数据；失效注入标签、地形真值、真实速度误差仅用于训练监督和离线评估。

训练数据覆盖四种健康组合及其转移，加入持续断流、冻结、全无效、局部遮挡、噪声、偏置、地图陈旧与位姿误差。失效需持续若干真实时间，而不是每个控制步独立随机更换状态；也要覆盖同时退化的共同原因。

初始监督损失可为 `BCE(p_v,y_v) + BCE(p_l,y_l)`。全断流等明确故障可以直接标注不可用；轻度噪声不应一律标故障，应结合保留数据上的单分支闭环表现确定可用范围。分数在独立地形、故障强度和实测数据上校准，再确定决策阈值。

第一阶段固定 RENet 参数，使用独立质量编码器或 detach 后的分支特征，避免训练选择器时改变已学好的动作策略。硬故障规则始终可以否决网络选择。

原始 RENet 使用两帧深度自编码器的输入重建误差，并通过低通滤波控制 VP/OP 切换；它的后备 OP 只依赖本体感知，而本项目的 LP 仍依赖雷达。因此双传感器方案需要额外判断 LP 是否可用。[原论文 §III-B](https://arxiv.org/html/2509.09283v1#S3.SS2)

该自编码器可以作为候选异常检测基线，但输入重建误差不等于地形估计误差，也不能单独证明传感器可靠。特别是：

- 当前地形辅助重建损失需要 Critic 的地形真值，不能直接作为实机在线判据。
- 当前 VP 地形目标按 minibatch 标准化，LP 使用固定裁剪目标，两者原始 MSE 不能直接比较大小来选模式。
- 两路预测不一致只能说明存在分歧，无法仅凭分歧确定哪一路正确；两路共同出错也可能一致。

## 3. SAFE 策略：学习从运动状态停止并持续平衡

建议新增独立任务 `g1_safe_stand`，单独输出 `safe_policy.pt`。这些名称是计划接口，目前尚不存在。

Actor 仅使用本体观测历史和停止目标。可沿用 78 维每帧的观测定义及 23 维关节动作契约，但必须独立核对尺度、归一化器、关节顺序、默认姿态、PD 参数和控制周期。上一动作历史应使用最终发给执行链路的动作，执行延迟也要在训练和部署中一致处理。

如需要接触或线速度输入，使用实机确实可获得的接触/速度估计，并模拟误差；不要将仿真真实根部线速度、射线足高或理想接触标签混入 Actor。Critic 和奖励可以使用这些真值。

SAFE 进入时立即由本体策略接管，并把最终运动目标设为零。动作仍由闭环控制逐步消除动量，允许必要的平衡步和摆动脚落地。若采用中间速度命令斜坡或目标变化率限制，要把同样机制纳入训练。不要先继续使用两路失效的 RENet 等机器人停下再切 SAFE。

训练课程：

1. 平地站立和抗小扰动，学习直立、减小角速度及滑移。
2. 从 LP 与 VP 的行走轨迹中采样状态，在不同前进/侧向速度、转弯状态、步态时刻触发 SAFE，学习停止过渡。优先使用前缀 rollout；若使用状态快照，要保留关节速度、基座速度、观测历史及相关执行延迟状态。
3. 加入坡面、粗糙地面、可支撑台阶、摩擦和执行器随机化、推力以及检测延迟期间已经发生的偏差。
4. 从停止后的状态长时间保持，验证小扰动后仍能站稳，再验证传感器恢复后的重新接管。

仅从默认站姿 reset 训练，不能覆盖单脚支撑、高速转弯等故障发生时刻。安全策略进入后的数据不能只包含理想、无延迟的切换状态。

奖励目标应覆盖：停止平移和旋转、保持身体方向和适当高度、抑制脚滑、限制动作跳变和关节负荷、避免非足部碰撞与跌倒。姿态跟踪采用适度权重，使策略仍能调整脚步恢复平衡；支撑与足滑要求按停止阶段调整，避免一开始就强迫摆动腿冻结或同时压地。

第一版推荐使用独立 PPO 奖励训练。当前 RENet 的 AMP 数据偏向行走/转向，不能直接假定适合持续静止；若加入 AMP，应准备停止和站立轨迹并验证其与安全目标一致。

SAFE 不是固定关节角输出，也不是关节力矩置零。前者缺少针对动态进入状态的平衡能力，后者会撤掉支撑控制。现有 `g1_recovery` 是另一类恢复任务，不能未经训练和验证就当作停止站立策略。

## 4. 接入位置

| 文件或模块 | 计划修改 |
|---|---|
| `legged_lab/envs/g1/RENet_env.py` | 在传感器处理前增加故障注入和视觉原始健康指标，输出与策略输入对齐的健康诊断 |
| `legged_lab/perception/lp_height.py` 及其调用侧 | 将高程、置信度、包龄关联到同一次消费，区分新采集与重复读取 |
| 新增共享感知监督器模块 | 规则/学习质量评估、三状态逻辑、迟滞、恢复条件、原因日志 |
| 新增 `g1_safe_stand` 环境和配置 | 停止站立任务、动态进入课程、本体 Actor、独立 Critic/奖励 |
| `legged_lab/scripts/play_new_renet.py` | 支持自动模式和 SAFE 策略加载，在动作推理前完成决策与命令覆盖 |
| `legged_lab/scripts/sim2sim_renet.py` | 复用同一监督器；在感知更新后、动作推理前选择 RENet 或 SAFE |
| 导出与评估流程 | 分别保存 locomotion、selector（如有学习模块）、safe 三类权重及观测契约 |

逻辑示意，不是可直接运行的现有 API：

```python
health = assess_sensor_health(raw_metadata, consumed_observations, proprio)
mode = supervisor.update(health, now, body_state)

if mode == SAFE:
    command = stop_target  # 拦截外部速度命令，目标为零
    action = safe_policy(build_safe_obs(proprio_history, command))
else:
    command = supervisor.limit_resume_command(user_command)
    mask = 1.0 if mode == LP else 0.0
    action = renet_policy(build_renet_obs(command, mask))

apply_action_with_validated_limits(action)
```

监督器健康检查应独立于故障传感器的阻塞读取，否则传感器断流时连 SAFE 也无法调用。初始模式不得默认认可尚未初始化的 LP 地图。

当前网络先计算两路 latent 再相乘，因此未选分支的 NaN 仍可能通过 `NaN * 0` 污染动作。输入有限性处理或分支隔离必须显式验证；不能把张量乘零理解为故障隔离。SAFE 推理路径不应依赖两路外部感知网络成功执行。

不推荐对 LP/VP 的二值 mask 直接做连续插值；它会让 Actor 收到原训练未覆盖的两路同时非零输入。动作混合、目标变化率限制同样需要实际闭环验证，不能当作稳定性的证明。

## 5. 训练和验收顺序

1. **保留现有 checkpoint，建立评估基线。** 分别测 LP/VP 在有效输入下的控制表现，以及人工切换时的动作变化。
2. **实现健康诊断、四类故障注入与规则监督器。** 可先做离线决策或仿真评估；没有训练好的 SAFE 策略时，不宣称已经实现安全降级。
3. **独立训练并验证 SAFE。** 重点测来自两个分支的动态进入、停止时间、停止位移、跌倒率、站立持续性与关节负荷。
4. **联调三个状态。** 测断流、冻结、噪声、地图过期、单路恢复、两路交替故障和频繁恢复抖动，检查故障分支是否被选中、切换延迟和恢复条件。
5. **需要更强感知识别时训练质量网络。** 与规则基线比较故障漏检、误判、闭环跌倒与任务完成率，再决定是否采用。只在切换控制性能不足时进行有针对性的策略微调。

数据划分按地形、故障类型和采集序列区分，避免邻近帧同时出现在训练和测试中。所有停止与恢复判据使用有单位的物理量和持续时间，阈值由仿真及后续受控硬件验证确定。
